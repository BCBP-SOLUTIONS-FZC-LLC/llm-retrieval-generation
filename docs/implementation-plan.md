# Implementation Plan — retrieval-generation (Python 3.15 / FastAPI)

Source of truth: `docs/lld/llm-lld-retrieval-generation-service.md` (6,664 lines, "LLD"). This file is the resume point
and, at the end, the traceability matrix. Status legend: `[ ]` not started, `[~]` partial, `[x]` done and tested.

## Phase 1 — Analysis

### Deployable
One FastAPI service (`retrieval-generation`) with six internal modules (LLD §3.1): `corpus`, `retrieval`, `generation`,
`verification`, `workflows`, `packs`, plus `corpusscope` (vendored library, sole importer of Qdrant, DEP-1).
Two Postgres instances: `llm_corpus` (collections, grants, index_generations, retention, tenant_lifecycle) and
`llm_generation` (artefacts, runs, retrieval record, verification, refinements, audit chain, outbox, processed_events).

### Scope cuts taken from the LLD itself (recorded as assumptions)

### Technology assumptions (LLD names all of these; none are introduced by us)
- Python 3.15, FastAPI, `platform-fastapicommon` (app factory, RFC 9457 errors, metrics, tracing, logging),
  `platform-pgcommon-py` (asyncpg Pool, GUC/RLS, `run_in_tx`, migration Runner), `platform-eventcommon`
  (Envelope, outbox enqueue/relay, inbox, SQS consumer, Codec).
- External clients: `temporalio`, `qdrant-client` (only inside `corpusscope`), Valkey via `redis`, `boto3` (S3), outbound HTTP via
  `fastapicommon.propagation.create_platform_http_client`.
- `iam-org-membership` is a Go service; its **layering, error taxonomy, outbox/inbox usage, RLS conventions, test pyramid** are the
  reference. Python mechanics come from the three shared libs' `__all__` surfaces and examples.
- Postgres 18 (`uuidv7()`); integration tests use testcontainers `postgres:18` and are skipped when Docker is unavailable.
- Layers (user-mandated) x modules (LLD): each layer holds module subpackages. DEP-1..5 enforced by `tests/architecture/test_dependency_rules.py` (ast walk).
