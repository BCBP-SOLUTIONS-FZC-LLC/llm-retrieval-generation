# Changelog

All notable changes to this service are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning aligned with SemVer ([VERSIONING.md](./VERSIONING.md)).

This service has never been deployed to any environment — there is no released version yet, so everything lives under `[Unreleased]`. Because of that, this file tracks what is currently true and what is still outstanding, not a slice-by-slice build history; the full development diary (per-slice deviations, assumed peer contracts, the traceability matrix) is in [`docs/implementation-plan.md`](docs/implementation-plan.md), and the design is the LLD at `docs/lld/llm-lld-retrieval-generation-service.md`.

### Added

- **Service foundation.** FastAPI app factory over `fastapicommon.create_platform_app`; settings carrying every LLD §17 variable at its documented default; two `pgcommon` pools (`llm_corpus`, `llm_generation`) behind PgBouncer in transaction mode with the tenant GUC bound transaction-locally; startup refuses any `PG_BOUNCER_MODE` other than exactly `true` (ISO-11); RFC 9457 errors with the 32-code taxonomy (§24); outbox wiring on both databases.
- **Corpus module (P-1, P-2, P-3, P-6; C-I1, C-I2, C-I4, C-I5, C-I6, C-I8).** Collections with deterministic UUIDv5 ids, grant overlay answers, index generations with trigger-enforced activation, retention policies with optimistic locking, tenant freeze/purge lifecycle, tender promotion by a second row and atomic cutover. `CollectionProvisioned`, `IndexGenerationActivated`, `CollectionPromoted` and `CollectionStatusChanged` are emitted by the corpus use cases.
- **`corpusscope` and retrieval (R-1, R-5, R-6, R-7, C-M1).** Scope tokens and the scope resolver (ordinary, restricted, tenant and reference branches, fail closed, 60 s cache), every Qdrant filter in one place, hybrid retrieval with RRF fusion, optional rerank, sufficiency verdicts, query refiner, required-input rules, classification proposal, model catalogue.
- **Generation and verification (R-2, R-3, R-4, A-1..A-4, A-9).** Two-phase SSE streaming (draft frames, then one verdict frame), producer tasks that survive a client disconnect, six-layer prompts with a nonce boundary and input screening, the tiered verification ladder (self-consistency, span overlap, entailment, judge), evidence tiers, completeness checks, structured extraction, S3 section content under tenant-prefixed keys with SSE-KMS, the append-only audit chain, idempotent admission.
- **Workflows and regeneration (W-1..W-8, A-5, A-6, A-7).** Temporal start and signal client behind a port (fail closed when `TEMPORAL_ADDRESS` is unset), run-row admission, guarded gate transitions, scope re-resolution on every signal (a revoked scope ends the run `failed/scope_revoked`), regeneration rules, fact-conflict resolution, the operator rematerialise route. The Worker Pool contract is `docs/worker-pool-contract.md`.
- **Events and sweeps.** 17 published event contracts with JSON Schemas derived from them (`schemas/events/`), fail-closed enqueue validation, one outbox relay per database through a routing publisher, six SQS consumers with DLQ forwarding at the fourth receive and an inbox ledger, ten sweeps run as `python -m rag.infrastructure.sweeps <name>|all` under per-instance advisory locks, a `rag_sweeper` role for cross-tenant enumeration.
- **Generated API contracts.** `docs/swagger/swagger.{json,yaml}` and `api/asyncapi.yaml` generated by `scripts/gen_api_docs.py` (`make swag`), `api/asyncapi.html` rendered from the AsyncAPI document, and drift checks (`make swag-check`, `tests/unit/test_api_docs.py`). Served at `/swagger` (Swagger UI with the BCBP theme), `/swagger/doc.json|yaml`, `/asyncapi` (themed event catalogue with an environment badge), `/asyncapi.yaml`, and a landing page at `/`.
- **Tooling.** `Makefile` mirroring `iam-org-membership` (`setup` bootstraps `uv` into the venv, `.env` created from `.env-example`, `lock`, `fmt`, `lint`, `typecheck`, `test`, `test-ci`, `test-e2e`, `swag`, `sweeps`, `migrate`, schema-governance targets); `uv.lock` with `make lock-check`; `make events-peek` to read the dev probe queue; `make extract-schemas` (and `swag` / `swag-check` covering `schemas/events/`), `make rls-check` (the RLS-6 grep, shared with CI), `make cover-check`, `make build`, and a `make ci` that mirrors the CI gates.
- **The gateway's wire details are settings.** The chat, embeddings, rerank, tokenize and models paths and the tenant, residency, plan and preferred-model header names (`GATEWAY_*_PATH`, `GATEWAY_*_HEADER`) are read from `Settings` instead of being hard-coded in `infrastructure/gateway/client.py`, so a different gateway is a configuration change and the service stays agnostic of any one product. Defaults are unchanged (Agent Router's). Paths must be absolute and header names valid, checked at startup. The task classes remain constants: they are the contract.
- **Local model gateway (opt-in).** `make gateway-up` starts the Agent Router image (`envoyproxy/ai-gateway-cli`, pinned to `v1.2.0`) with `deploy/model-gateway/aigw.yaml` in front of `scripts/model-stub` (deterministic chat, embeddings, Cohere-style rerank and tokenize; rate-limit, residency and malformed answers on command). `make test-gateway` runs 12 contract tests of our client against it; they are excluded from `make test`, CI and `test-ci`. Findings against v1.2.0: embeddings, chat (plain and streamed, usage on the last chunk), `/cohere/v2/rerank` and `/tokenize` work; `/v1/rerank` is a 404; an unconfigured task class is a 404; 429 with `retry-after` and a 503 `residency_capacity` body pass through unchanged; our `x-tenant-id`, `x-residency-mode` and `x-plan` headers reach the backend, and a route can match on `x-residency-mode`.
- **Local stack.** `docker-compose.yml` with two Postgres databases and a non-superuser login in `rag_app`, PgBouncer, Valkey, Qdrant, floci (S3/SNS/SQS) and floci-ui on host port 4501; `scripts/init-db.sql` and `scripts/init-floci.sh` (bucket, two topics, six queues, and `llm-events-probe-q` subscribed to both topics).
- **CI.** `.github/` with `ci.yml`, reusable `validate-test.yml` (unit + integration with coverage, the 95% gate, then e2e) and `validate-quality.yml` (lock check, `uv pip check`, RLS-6 grep, format, lint, `mypy --strict`, `pip-audit`), `changelog-check.yml`, SHA-pinned actions, `CI_REPO_READ_TOKEN` for the private packages, CODEOWNERS (`@BCBP-SOLUTIONS-FZC-LLC/llm-team`), issue and PR templates, `SECURITY.md`.
- **Tests.** About 1,270 tests: unit, use-case, API, architecture, events, isolation, repository and integration suites (real `postgres:18` via testcontainers), and 32 end-to-end tests over a real RLS Postgres (`make test-e2e`). Coverage is about 97.8% for unit + integration.
- **Documentation.** `README.md`, `CONTRIBUTING.md`, `VERSIONING.md` (with a *Planned* table for the machinery that does not exist yet), `ARCHITECTURE.md`, `docs/` runbooks and observability notes, `.claude/` working notes, and `.githooks/pre-commit`.


- **Events: outbox on both databases (decision).** Corpus events must share the state change's transaction (EVT-8) and a transaction cannot span two databases, so `llm_corpus` carries its own outbox. OBX-3's "one relay" is met as one claim loop per table, all publishing through one routing publisher that picks the topic by event type name. `migrate_all` applies the outbox schema **before** the numbered sets because `0003` grants on tables the library owns.
- **Envelope corrections against §12.2.** `source` is `llm-rag-service`; `subject` is `tenders/<tender_id>` or absent; `correlation_id` propagates.
- **`reject_generation_transition` uses `pg_has_role` membership** instead of `current_user = ANY(names)`: login roles are members of the NOLOGIN groups, so the literal LLD check would reject every write (same intent, deviation from the text).
- **EVT-14 implemented as read-under-the-claimed-tenant**, refusing when the row is absent or its tenant differs from the envelope's — the literal "read outside any tenant context" cannot work under `FORCE` RLS with no `BYPASSRLS` role.
- **Cross-tenant sweep enumeration** uses a deliberate path: NOLOGIN role `rag_sweeper` with column-limited `SELECT` and a `FOR SELECT … USING (true)` policy per table. Needs platform sign-off.
- **Retrieval-set orphan retention** is configurable (`RETRIEVAL_SET_ORPHAN_MIN_AGE_DAYS`, default 30, LD-101).

### Fixed

- **Concurrent first-document race on `uq_coll_tender`.** `collections.insert` now uses `ON CONFLICT DO NOTHING` plus an existence check, so two concurrent C-I1 calls compute one primary key and resolve on insert; a genuine slot conflict under a different id still raises (COL-9). Found by running the corpus integration tests on real Postgres.
- **`asyncpg` refused a `UUID` for a `$1::text` advisory-lock key** in the generation write path; the key is now passed as text.
- **Immutability triggers** on append-only tables use `reject_always`: `reject_update_except()` with no arguments is a no-op (empty `TG_ARGV` is `NULL` in PL/pgSQL).
- **CI-1 route scan** was blind to routes added through `include_router` under FastAPI 0.16; it now walks included routers.
- **All database access goes through `platform-pgcommon-py`.** The last direct `asyncpg` import is gone: COL-9's slot conflict is raised as `CollectionSlotConflict` (SQLSTATE 23505 and the constraint name, which `pgcommon.is_unique_violation` / `constraint_name` read, so it classifies like the database's own error). Every pool (application, sweeps, migration) is now configured by one factory, `pool_config`, whose tuning comes from `pgcommon.config_from_env`: the library's `PG_STATEMENT_TIMEOUT`, `PG_LOCK_TIMEOUT`, `PG_ACQUIRE_TIMEOUT`, `PG_SLOW_QUERY_THRESHOLD`, `PG_MAX_CONN_LIFETIME` and the rest are now honoured (they were ignored, and the library's configuration warnings were never logged; a bad value now becomes its default plus one `pgcommon_config_warning`). Still ours, because they are security or topology decisions: the DSNs (two databases), pool name and size (`PG_MAX_CONNS` must equal PgBouncer's pool size, so it fails at startup), PgBouncer mode (exactly `true`) and the tenant GUC provider. `tests/architecture/test_database_access_only_through_pgcommon.py` fails on a driver import, on `pgcommon` in `domain`/`application`, and on a second builder of a `Config`; verified against real Postgres and PgBouncer.
- **All logs go through `platform-fastapicommon`.** The 20 modules that logged with the standard library's `logging` now use `fastapicommon.logging.get_logger` with structured calls (an event name plus fields, for example `log.warning("run_close_failed", error=...)`), and the sweep CLI configures logging with `configure_logging` instead of `logging.basicConfig`. The architecture test lets the application layer import exactly one platform module, `fastapicommon.logging`; `domain` stays standard-library-only. `tests/architecture/test_shared_libs_only.py` now fails on any stdlib `logging`, `structlog`, `prometheus_client` or `opentelemetry` import in `src/`, and on an application-layer import of any other `fastapicommon` module. Log events have new names and fields (for example `poison_event` logs the exception type, not its message). Metrics and tracing were already built only from `fastapicommon.metrics` and `fastapicommon.telemetry`.
- **Settings accepted nonsense.** `RRF_K=-5`, `PAGE_LIMIT_MAX=0`, a non-UUID `COLLECTION_NAMESPACE`, a non-Postgres DSN, thresholds outside [0, 1], a request timeout not above R-4's 90 s budget and `EVENTS_ENABLED=true` with no topic ARNs were all accepted and failed later or not at all. Counts, durations, shares and thresholds now carry range checks, DSNs must be `postgresql://`, and cross-field rules (§17) are checked in one model validator, so the service stops at startup.
- **Down migrations were never executed.** Their only test needed `pglast`, which is not a dependency, so it was skipped. `tests/repository/test_migrations_roundtrip.py` now migrates each database up, all the way down and up again.
- **Local `make run` without a `.env`** connected to `localhost:5432` and failed on start; the Makefile now creates `.env` from `.env-example`.
- **A stray `.env` leaked into unit tests**; an autouse fixture now ignores it.
- **`make swag-check` title drift** when the Makefile exported `APP_NAME`; the generator pins the app name.

### Known gaps

Outstanding as of this entry. None of these is a regression; they are what is not built or not verified.

- **No Worker Pool.** Long-form runs (W-1, W-6, A-5) can be admitted and signalled but nothing executes them: outline, stage and coherence activities, `OutlineReady`, gate expiry and the suspend path are untested end to end. The LangGraph graphs belong to that service.
- **No peer has been exercised for real.** Nothing has run against a real Temporal server, Tender, IAM or S3, and the Model Gateway has only run in standalone mode in front of a model stub (no real model, no Bedrock, no quota, no Kubernetes); the Gateway routes (`/v1/embeddings`, `/cohere/v2/rerank`, `/v1/chat/completions`, `/tokenize`, `/v1/models`; listed in the product's documentation, never run), the Tender pack JSON and the IAM bodies are assumptions, listed per slice in the implementation plan. Qdrant and Valkey run in compose but no test exercises the real adapters.
- **Glue event encoder (LD-82) not built**, so published events are not framed for the schema registry.
- **`/ready` does not reflect the outbox relay** (`app.state.relay_ready` exists; the probe is not wired).
- **Unbuilt sweeps and checks:** zombie-run and orphan-S3-object sweeps, the retention sweep (LLD-deferred), the corpus-wide conflict check (LD-52, deferred past v1); REGEN-5 reuse; scope-cache invalidation on collection writes; tenant purge reaching Valkey keys and evaluation samples; the reference-collection seed.
- **A-8 render** answers `503 RENDERER_UNAVAILABLE` by design (scope cut S-6).
- **Metrics are disabled by default**: the `llm` domain is not registered in the platform registry (OQ-103).
- **Image pipeline never completed on GitHub:** `Dockerfile`, Helm chart, `release.yml` and the `ci.yml` jobs `Build image (cache)`, `Trivy CVE scan` and `Smoke tests` (the checks the org ruleset on `main` requires) exist, but Actions jobs did not start because of an account billing limit. See [VERSIONING.md](./VERSIONING.md).
- **Decisions awaiting sign-off:** the `rag_sweeper` role, `pg_has_role` in the generation trigger, one relay per database, the extra run edges to `scope_revoked`, cancelled-run closure for content refusals.

### Current architecture notes

- Clean Architecture layers (`domain` → `application` → `infrastructure` / `presentation`) with six LLD modules and the vendored `corpusscope` library; the layer and DEP-1..4 rules are enforced by `tests/architecture`, DEP-5 by database role grants.
- Two Postgres 18 instances behind PgBouncer in transaction mode, RLS `ENABLE` + `FORCE` on every table except `processed_events` and the outbox, tenant GUC bound transaction-locally only.
- 35 routes (27 public, 6 internal, 1 operator, C-M1); 17 published and 11 consumed event types on two topics and six queues.
- Specs are generated from code and committed; CI fails on drift.
